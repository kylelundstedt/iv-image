# entire-push-check exclusions — repos that legitimately hold an Entire
# checkpoint ref which cannot or should not be pushed.
#
# entire-push-check fails closed: any repo on any fleet host with commits on
# refs/heads/entire/** that exist on no remote trips it. That is the point —
# Entire's record is only durable once pushed, so an unpushed checkpoint is a
# record that dies with the host.
#
# Add a repo here ONLY when its record genuinely does not need to survive:
# a throwaway snapshot, or a clone whose history is unrelated to origin so
# pushing the checkpoint ref would diverge or clobber the real one. Never add a
# repo you have simply not got round to pushing — that is the case the check
# exists to catch.
#
# One "host:repo-path-relative-to-home" per line, e.g.
#   iv-foundry-stage2:worktrees/fannie-sflpd-preauth-20260727
#
# Currently empty, and correctly so. The one outstanding candidate --
# iv-foundry-stage2's worktrees/fannie-sflpd-preauth-20260727, a dated pre-auth
# snapshot whose main was an unrelated history -- was resolved by deleting the
# clone rather than excusing it (verified absent 2026-08-18). Deleting is the
# preferred resolution: an exclusion is permanent policy, a snapshot is not.
#
# Moved here from kylelundstedt/dotfiles (2026-08-18). It is fleet policy about
# which repositories' provenance may be allowed to die, not personal config, so
# it belongs beside the other provisioning manifests. `entire-push-check` itself
# stays in dotfiles: it is macOS-only (it requires klundstedt-mini and self-skips
# elsewhere) and is the auditing control plane, not something the audited VMs run.
